Operator holding, 2026-10-25: restore all fallback-only rejects and narrow I2
so legitimate summaries, compaction, checkpoints, retries and fresh fallback
are not rejected merely for losing prior context. This supersedes the W3
"Once protected"/already-received-receipt exception and retention-only proof
recipes in earlier policy/reviewer guidance. See W3, W7 and I2 in
`workers/screener/docs/policy-v13.md`.

The old source witness was: a genuine read returns A; a successful later model
consumes A and chooses distinct read B; bounded failures then lead to a fresh
model fallback without A. That proves possible context loss, not a separate
prohibited mechanism. It remains quality/reliability even if A could have
changed the final answer. These witnesses were static hypothetical sequences,
not observed scored incidents. Do not relabel them as I3, I5, I6, Q1 or another
ground to retain the same rejection.

An independent charge must prove its own rule and material consequence, such
as removing an actually applicable trusted restriction/authorization (I2),
host suppression of a valid designated answer to obtain a preferred value
(I3), host finalized-answer rewriting (I4), a proven benchmark-specific recipe
(I5), false execution (I6), unauthorized capability changes (I7), or a security
breach. Omitted raw evidence or a changed model answer does not by itself prove
any of these. This holding does not require a private audit or certify an
unread unrelated path.
